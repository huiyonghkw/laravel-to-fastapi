EP01 · 心智模型

Laravel 帮你藏起来的事，
FastAPI 让你写出来

上手 FastAPI 不用学新语言，只换一层心智：依赖注入、异步，Laravel 替你藏进容器，FastAPI 让你显式写出来。本篇把这两点拆开讲透，看完直接能跑。

01

一句话心智模型

两个框架做的事一模一样——把依赖送进函数、让请求并发。差别只在：Laravel 帮你自动做（服务容器、PHP-FPM 同步）；FastAPI 让你自己写出来（Depends、async）。

Laravel 的心智
  • 依赖？构造器写个类型，容器自动 new 好
  • 并发？不用管，PHP-FPM 一个请求一个进程
  • 你只管写业务逻辑
FastAPI 的心智
  • 依赖？用 Depends 声明，框架送进来
  • 并发？async/await 自己标，事件循环复用进程
  • 控制权在你手里
一句话：Laravel 是「你别管，我搞定」；FastAPI 是「你写清楚，我执行」。概念没变，只是从隐式变显式。
02

对照①依赖注入（基础）

都是「调用方声明要什么，框架把实例送进来」。左 Laravel 靠容器，右 FastAPI 靠 Depends。

Laravel 13 · PHP
// UserController.php public function show( private UserRepo $users // 容器自动注入 ) { return $users->find($id); }
FastAPI 0.140 · Python
# ep01.py def get_db(): db = Session() try: yield db # 请求期间注入 finally: db.close() @router.get('/user/{id}') def get_user(db = Depends(get_db)): return db.find(id) # 直接拿到实例
Depends(get_db) 和 Laravel 构造函数类型提示同构。yield 还能管生命周期——请求结束自动 close，等于容器的析构。
03

对照②依赖注入（嵌套 + 缓存）

真实项目里依赖是链式的：A 依赖 B，B 依赖 C。两边都会顺着链解析，且同一请求内只解析一次（FastAPI 叫依赖缓存，Laravel 是请求级作用域）。

Laravel 13 · PHP
// 容器顺着构造器解析链 class AuthService {} class UserService { public function __construct( private AuthService $auth // 容器先 new AuthService ) {} } // 同一请求内 AuthService 只建一次
FastAPI 0.140 · Python
# Depends 套 Depends def get_token(): return 'tok' def get_user( t: str = Depends(get_token) ): return {'u': 'alice'} @router.get('/me') def me(u = Depends(get_user)): return u # get_token 只跑一次
Laravel 用 App::singleton() 控制「只建一次」；FastAPI 默认同一请求内缓存依赖结果，想每次都重建就加 Depends(fn, use_cache=False)。
04

对照③同步 vs 异步（基础）

这是 Laravel 老手最大的体感差：把函数标成 async、I/O 前加 await，进程就能在等待时去接别的请求。

Laravel 13 · PHP
// 同步：等 DB 时进程空转 Route::get('/slow', function () { $data = DB::table('x')->get(); // 阻塞 return $data; });
FastAPI 0.140 · Python
# 异步：等 I/O 时让出进程 @router.get('/slow') async def slow(): data = await db.fetch('x') # 让出控制权 return data
规则很简单：碰到 I/O（查库、调接口、读文件）就 await；纯计算不用。一开始全写 async def 也不会错，FastAPI 兼容同步写法。
05

对照④异步（并发才显价值）

异步真正的红利是并发：多个 I/O 一起等，而不是排队等。下面左是顺序（慢），右是 asyncio.gather（快一倍）。

顺序（慢）
# 两次 I/O 排队，耗时相加 async def batch_seq(): a = await fetch('A') # 先等 A b = await fetch('B') # 再等 B return {'a': a, 'b': b}
并发（快）
# 两个 I/O 同时发起 @router.get('/batch') async def batch(): a, b = await asyncio.gather( fetch('A'), fetch('B')) return {'a': a, 'b': b}
Laravel 要走并发得靠队列（dispatch + Worker），FastAPI 在单进程内用 asyncio.gather 就能并发——这是 AI 流式响应快的关键。
06

⚠️ Laravel 老手常见坑

坑 1 · 把阻塞写进 async：time.sleep、同步 DB 驱动（pymysql）会卡死整个事件循环。I/O 一律用 await 的异步库（asyncpg / httpx / aiosqlite）。
坑 2 · 忘了 Depends：直接在函数里 Session() 也能跑，但你就失去了注入、缓存和测试时替换实现的便利——和 Laravel 里不写类型提示、自己 new 一样别扭。
坑 3 · 依赖缓存误以为每次都新建：同一请求内 Depends(get_db) 默认只执行一次。需要每次新建（如写测试）就 Depends(get_db, use_cache=False)。

08

上手练习（10 分钟）

给 /ep01/me 加一层「必须登录」：新建一个 get_current_user（已在示例里），再写一个受保护端点——

FastAPI · 你的练习
# 在 ep01.py 末尾加： @router.get('/profile') def profile(u = Depends(get_current_user)): return {'hello': u['user']}
做完你会发现：这和 Laravel 里 ->middleware('auth') 保护路由是同一件事，只是 FastAPI 用 Depends 把「当前用户」显式注入，而不是藏在中间件里。
