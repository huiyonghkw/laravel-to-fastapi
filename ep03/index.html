EP03 · 控制器 vs 路径操作

逻辑放哪这件事

Laravel 把一批接口收进一个 Controller 类；FastAPI 直接写函数，函数就是「路径操作」。同一个 endpoint，左边是类里的一个方法，右边是装饰器下的一个 def。本篇讲清这层「包装」差异。

01

一句话心智模型

两边最终都是「一个 endpoint = 一段处理逻辑」。差别只在「这段逻辑以什么形态存在」：Laravel 把它塞进 Controller 类的方法；FastAPI 让它独立成一个函数，再用 APIRouter 把同类函数归一组——这组函数就等于 Laravel 的一个 Controller。

Laravel 的控制器
  • 逻辑收进 UserController 类
  • 每个接口 = 类里一个 public function
  • 路由用 [Controller::class, '方法名'] 指过去
FastAPI 的路径操作
  • 逻辑就是普通函数，没有类包装
  • 每个接口 = 一个被装饰的 def
  • 用 APIRouter 把一组函数收在一起
一句话：Laravel 是「类的方法」，FastAPI 是「独立函数」。控制器只是组织习惯，FastAPI 用 router 达到同等组织力。
02

对照①整体形态：类 vs 函数组

同一个「用户模块」，左右的组织方式。右 FastAPI 的 @router.* 三个函数，正好等价于左 Laravel 的 UserController 三个方法。

Laravel 13 · PHP
// app/Http/Controllers/Api/UserController.php class UserController extends Controller { // 列表 → 对应 list_users public function show(int $user_id) { return response()->json([ 'user_id' => $user_id]); } // 新建 → 对应 store_user public function store(Request $request) { $data = $request->validate([...]); return response()->json( ['received' => $data]); } }
FastAPI 0.140 · Python
# fastapi/app/ep03.py router = APIRouter() # ← 这组函数 = 一个 Controller @router.get("/users") def list_users(): return {"users": []} @router.get("/users/{uid}") def show_user(uid: int): return {"uid": uid} @router.post("/users") def store_user(): return {"created": True}
注意左 Laravel 的 show 收标量参数，右 FastAPI 的 show_user 用类型提示 uid: int 自动转换——这是 EP02 讲过的路径参数，这里套在「函数即 handler」的壳里。
03

对照②路由怎么指过去

Laravel 在路由文件里用字符串方法名「点名」控制器方法；FastAPI 不需要中间一层——装饰器已经把 URL 和函数绑死了。

Laravel 13 · PHP
// routes/api.php（EP03 段） Route::get('/users', [UserController::class, 'index']); Route::get('/users/{uid}', [UserController::class, 'show']);
FastAPI 0.140 · Python
# 装饰器即绑定，无中间层 @router.get("/users") def list_users(): return {"users": []} @router.get("/users/{uid}") def show_user(uid: int): return {"uid": uid}
左 Laravel 的 'index' / 'show' 是字符串方法名，拼错会运行报 MethodNotAllowed / NotFound；右 FastAPI 的 list_users / show_user 只是函数名，真正决定 URL 的是装饰器参数，函数叫什么无所谓。
04

对照③写操作 + 请求体

POST 新建用户：Laravel 在控制器里拿 Request 对象并 validate；FastAPI 这边先放一个最简骨架（Pydantic 校验留到 EP05 细讲）。

Laravel 13 · PHP
// routes/api.php Route::post('/users', [UserController::class, 'store']); // UserController::store public function store(Request $request) { $data = $request->validate([ 'name' => 'required|string', 'email' => 'required|email', ]); return response()->json( ['received' => $data]); }
FastAPI 0.140 · Python
# routes/api.php 等价于： @router.post("/users") def store_user(): # 校验与请求体见 EP05（Pydantic） return {"created": True}
左边 $request->validate([...]) 是「方法内部校验」；右边把同样的事交给 EP05 的 Pydantic 模型——FastAPI 的惯用法是「函数签名即契约」，比在方法体里写规则更靠前。
05

⚠️ Laravel 老手常见坑

坑 1 · 硬套 Controller 类：FastAPI 没有「控制器」这层概念。新手常写一个 class UserController 再 @router.get 挂方法——没必要。一组函数 + 一个 APIRouter 就是最地道的写法。
坑 2 · 方法名拼错：[UserController::class, 'indx'] 这种拼写错误只有运行时才炸；FastAPI 没有字符串方法名，装饰器直接绑定，少一层出错面。
坑 3 · 参数名不对应：Laravel 路由 {uid} 和控制器参数 $user_id 名字可以不同（按位置注入）；FastAPI 必须同名——函数参数 uid 对应路径 {uid}，写错名会 422 / 拿不到值。
06

07

上手练习（10 分钟）

给「用户模块」加一个更新接口 PUT /ep03/users/{uid}，左右各补一处：

FastAPI · 你的练习
# 在 ep03.py 中加： @router.put("/users/{uid}") def update_user(uid: int): return {"uid": uid, "updated": True}
Laravel 侧则在 UserController 加一个 public function update(int $uid)，并在 routes/api.php 加一行 Route::put('/users/{uid}', [UserController::class, 'update'])。做完你会发现：两边都是「加一个方法 + 加一条路由」，组织结构完全同构，只是左在类里、右在函数里。
