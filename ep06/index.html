EP06 · ORM

把数据表变成对象

ORM 就是「让数据库行当成一个普通对象来用」。Laravel 给的是 Eloquent（Model 即表）；FastAPI 通常配 SQLAlchemy 2.0（先定义模型类，再用 session 查）。本篇讲清两边如何定义模型、怎么写关联、怎么查询。

01

一句话心智模型

无论是 Eloquent 还是 SQLAlchemy，本质都是「一张表 ↔ 一个类，一行 ↔ 一个对象」。Laravel 把 CRUD 方法直接挂在 Model 上（静态调用）；FastAPI/SQLAlchemy 把操作交给一个独立的 session 对象。

Laravel · Eloquent
  • Model 类就是一张表，Post::all() 直接查
  • 关联写在 Model 里：hasMany() / belongsTo()
  • 方法多为静态/实例调用，框架接管连接
FastAPI · SQLAlchemy 2.0
  • 模型类继承共享 Base，用 Mapped 声明字段
  • 关联用 relationship() 等价 hasMany
  • 查询走 session.execute(select(...))（SQLAlchemy 2.0，别用 legacy db.query）
一句话：Laravel 是「Model 自带 CRUD」，SQLAlchemy 是「对象 + session 分离」。同一个心智，两种不同的落笔。
02

对照①模型定义

先声明「表长什么样」。左 Laravel 用 $fillable + 关联方法；右 FastAPI 用 Mapped / mapped_column + relationship。字段、外键、关联一一对应。

Laravel 13 · PHP
// app/Models/Post.php class Post extends Model { protected $fillable = ['title']; public function comments() { return $this->hasMany(Comment::class); } } // app/Models/Comment.php class Comment extends Model { protected $fillable = ['body', 'post_id']; public function post() { return $this->belongsTo(Post::class); } }
FastAPI 0.140 · Python
# app/ep06.py（继承共享 Base） class Post(Base): __tablename__ = "ep06_posts" id: Mapped[int] = mapped_column(primary_key=True) title: Mapped[str] = mapped_column(String(255)) comments: Mapped[list["Comment"]] = \ relationship(back_populates="post") class Comment(Base): __tablename__ = "ep06_comments" id: Mapped[int] = mapped_column(primary_key=True) body: Mapped[str] = mapped_column(String(255)) post_id: Mapped[int] = mapped_column( ForeignKey("ep06_posts.id")) post: Mapped["Post"] = \ relationship(back_populates="comments")
relationship(back_populates=) 等价于 Eloquent 的 hasMany + belongsTo 双向关联；String(255)、ForeignKey(...) 对应 Laravel 迁移里的字段类型与外键。
03

对照②关联查询 with('comments')

「取文章、连同它的评论一起」——Laravel 用 with('comments') 预加载；FastAPI 因为 relationship 已声明，直接访问 .comments 即可（SQLAlchemy 2.0 默认会话内惰性加载）。

Laravel 13 · PHP
// PostController@index public function index() { // with() 预加载，避免 N+1 查询 $posts = Post::with('comments')->get(); return response()->json($posts); }
FastAPI 0.140 · Python
# ep06.py · list_posts（2.0 select + joinedload） @router.get("/posts") def list_posts(db=Depends(get_db)): stmt = select(Post).options( joinedload(Post.comments)) rows = db.execute(stmt).unique().scalars().all() return [ {"id": p.id, "title": p.title, "comments": [c.body for c in p.comments]} for p in rows ]
两边都能拿到 post.comments。差别：Eloquent 默认惰性加载（不写 with 会触发 N+1），所以要显式 with；SQLAlchemy 2.0 在 session 内访问关联也会发 SQL，同样要注意 N+1（可用 joinedload 预加载）。
04

对照③新增与写入

「存一条数据」。Laravel 的 Model::create() 一行搞定；FastAPI 要 add() + commit()，因为是 session 托管写入。

Laravel 13 · PHP
// Eloquent：静态 create 一步提交 $post = Post::create(['title' => 'Hi']); $post->comments()->save( new Comment(['body' => 'nice']));
FastAPI 0.140 · Python
# SQLAlchemy：add + commit post = Post(title="Hi") db.add(post) db.commit() db.refresh(post) # 拿回生成的主键 comment = Comment(body="nice", post=post) db.add(comment) db.commit()
commit() 才真正落库，相当于 Eloquent 在请求结束自动 flush 的那一步；db.refresh(post) 把数据库生成的自增 id 同步回对象——Eloquent 的 create 内部已帮你做了。
05

⚠️ Laravel 老手常见坑

坑 1 · ORM 对象不能直接返回：FastAPI 路由里 return post（模型实例）会报错——它只认 dict / Pydantic / list。要像 ep06 那样手动转成 {"id": p.id, ...}，或配 response_model。
坑 2 · 会话要关：别把 session 当全局长连接一直用。get_db 用 try/finally: db.close() 在请求结束后关闭；用 Depends(get_db) 注入就自动回收。
坑 3 · 迁移得自己接：Eloquent 有 php artisan migrate；SQLAlchemy 没有内置迁移器。演示可 Base.metadata.create_all(engine)，真实项目要接 Alembic 管版本。

07

上手练习（10 分钟）

给 GET /ep06/posts/{id} 加一个按主键取单篇、并带评论数的接口：

FastAPI · 你的练习
# 在 ep06.py 的 router 上加： @router.get("/posts/{post_id}") def get_post(post_id: int, db=Depends(get_db)): post = db.get(Post, post_id) # 主键查询 if post is None: raise HTTPException(404) return {"id": post.id, "title": post.title, "comments": len(post.comments)}
做完你会发现：db.get(Post, post_id) 等价于 Eloquent 的 Post::find($id)；找不到时别忘了抛 HTTPException(404)——Eloquent 的 findOrFail 会自动 404，FastAPI 得自己写。
