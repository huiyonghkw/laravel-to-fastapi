EP09 · 依赖注入进阶

把对象「打包好」自动送进函数

依赖注入（DI）就是：你只声明「我需要什么」，框架负责造好并塞进来。Laravel 用服务容器 App::bind/singleton 解析；FastAPI 用 Depends 串成解析链。本篇讲清单例、嵌套依赖，以及最容易踩的三个坑。

01

一句话心智模型

两边都在做同一件事：「声明依赖 → 框架去解析 → 注入给你」。差别只在写法：Laravel 把绑定收进服务容器，靠类型提示自动解析；FastAPI 把依赖写成函数/类，用 Depends 串成调用链。

Laravel 的容器
  • App::bind() 每次解析都新建
  • App::singleton() 全进程只一份
  • 控制器构造器类型提示，容器自动注入
FastAPI 的 Depends
  • 依赖是函数或类，返回什么就注入什么
  • 模块级实例 ≈ singleton（全进程一份）
  • Depends(...) 嵌套 = 解析链
一句话：Laravel 是「容器绑定」思维，FastAPI 是「依赖函数」思维。同一个心智，两种落笔。
02

对照①单例：容器绑定 vs 模块级实例

「全进程只保留一份」——左 Laravel 用 App::singleton()，右 FastAPI 用模块级实例 + 一个返回它的依赖函数。

Laravel 13 · PHP
// AppServiceProvider::register() app()->singleton(Counter::class, fn () => new Counter()); // 在别处解析——永远同一份 $c = app(Counter::class); $c->next();
FastAPI 0.140 · Python
# 模块级实例 = singleton _counter = Counter() def get_counter(): return _counter # 永远同一份 # 路径操作里注入 def count(c: Counter = Depends(get_counter)): return {'n': c.next()}
两种写法结果一样：计数在多次请求间累加，因为指向的是同一个对象。关键在「实例放哪」——Laravel 交给容器，FastAPI 放在模块作用域。
03

对照②嵌套依赖（解析链）

「A 依赖 B，B 又依赖 C」——两边都自动地从最里层往外解。左 Laravel 在绑定闭包里取容器里的配置；右 FastAPI 用 Depends 把 get_config 喂给 get_db_url。

Laravel 13 · PHP
// 容器解析时先拿到 config app()->bind(DbService::class, fn ($app) => new DbService( $app['config']->get('app.env') )); // 用的时候只拿结果 $url = app(DbService::class)->url();
FastAPI 0.140 · Python
# 依赖里再 Depends = 解析链 def get_config(): return {'env': 'dev'} def get_db_url(cfg: dict = Depends(get_config)): return f"db://{cfg['env']}" # 注入的就是拼好的 url def db_url(url: str = Depends(get_db_url)): return {'url': url}
FastAPI 的嵌套 Depends 等于 Laravel 容器逐层解析。get_db_url 自己不需要知道配置怎么来的，只声明「我依赖一个 dict」。
04

对照③在路由里注入（真实端点）

落到真实接口：左 Laravel 在路由闭包里直接用 config() 取配置；右 FastAPI 把依赖声明成路径操作的默认参数。两边返回结构一致。

Laravel 13 · PHP
// routes/api.php Route::get('/db-url', fn () => ['url' => 'db://' . config('app.env')] );
FastAPI 0.140 · Python
# fastapi/app/ep09.py @router.get('/count') def count(c: Counter = Depends(get_counter)): return {'n': c.next()} @router.get('/db-url') def db_url(url: str = Depends(get_db_url)): return {'url': url}
Laravel 直接在闭包里config()；FastAPI 用依赖把「取配置」这一动作解耦成函数——换实现、做测试时只替换依赖，路由本身不动。
05

⚠️ Laravel 老手常见坑

坑 1 · 单例状态跨请求累加：模块级实例 / singleton 是全进程一份，/count 每次都 +1，且所有请求共享。做计数器演示 OK，但放「每用户状态」会串号——那该用 request 作用域或数据库。
坑 2 · use_cache 让依赖在同请求内只跑一次：FastAPI 默认同一请求内缓存依赖结果（多次 Depends 同一函数只执行一次）。若依赖里有「每次都要重算」的逻辑（如时间戳、随机数），要 Depends(get_x, use_cache=False) 关掉缓存。
坑 3 · bind vs singleton 搞反：App::bind() 每次解析都 new 一个；App::singleton() 才只一份。FastAPI 里「模块级实例」对应 singleton，不是 bind。想每次新建就别用模块级变量，改在依赖函数里 return X()。

07

上手练习（10 分钟）

加一个带时间戳的依赖，并故意关掉缓存，看每次值不同：

FastAPI · 你的练习
# 在 ep09.py 里加： import time def now(use_cache=False): return time.time() @router.get('/now') def get_now(t = Depends(now, use_cache=False)): return {'t': t}
做完你会发现：加了 use_cache=False，同请求内多次调用也每次重算；去掉它则只算一次。这和 Laravel 容器「解析一次缓存结果」的心智一致——只是 FastAPI 把开关摆到了 Depends 上。
