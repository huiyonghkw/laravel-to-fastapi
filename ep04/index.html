EP04 · 请求与响应

进来的那一份包裹

每个请求都是一份「包裹」：URL、查询参数、请求头、请求体。两边都要先拆包裹（请求对象），再打包回信（响应对象）。本篇讲清两边怎么读、怎么回。

01

一句话心智模型

无论是 Illuminate\Http\Request 还是 FastAPI 的 Request，本质都是「把 HTTP 请求包成一個对象，让你随手取」；响应则相反——你返回数据，框架帮你包成 HTTP 响应。Laravel 用 $request 对象，FastAPI 用 Request 参数（或直接返回 dict）。

Laravel 的请求/响应
  • 入站：$request 对象（类型提示注入）
  • 读取：$r->path() / $r->header() / $r->input()
  • 回信：response()->json($d, 201)
FastAPI 的请求/响应
  • 入站：函数参数 req: Request
  • 读取：req.url / req.headers / Header(...)
  • 回信：直接 return dict 自动变 JSON，或 JSONResponse(...)
一句话：Laravel 是「对象方法」思维，FastAPI 是「类型提示 + 直接返回」思维。同一个拆包/打包心智，两种落笔。
02

对照①读取请求对象

「echo」端点：读当前路径和请求头里的 x-token。左右一一对应。

Laravel 13 · PHP
// routes/api.php Route::get('/echo', fn (\Illuminate\Http\Request $r) => [ 'path' => $r->path(), 'token' => $r->header('x-token'), ]);
FastAPI 0.140 · Python
# ep04.py @router.get('/echo') def echo(req: Request, x_token: Optional[str] = Header(None)): return { 'path': req.url.path, 'token': x_token, }
身体里的 Request 对象能拿到 URL、header、body；而 x_token: Header(None) 这种参数声明是 FastAPI 的「声明式取头」——Laravel 老手习惯用 $r->header()，FastAPI 把取头写成了函数签名。
03

对照②自定义响应（状态码 + 头）

要自己控制状态码和返回头时，两边都能显式打包响应，而不是让框架默认 200。

Laravel 13 · PHP
// 自定义 201 + 头（典型写法） Route::get('/custom', function () { return response()->json( ['ok' => true], 201) ->header('x-powered-by', 'laravel'); });
FastAPI 0.140 · Python
# ep04.py @router.get('/custom') def custom(): return JSONResponse( status_code=201, content={'ok': True}, headers={'x-powered-by': 'fastapi'})
对照《ep04.py》注释：JSONResponse(status_code=, content=, headers=) 正对应 Laravel 的 response()->json($d, 201)->header(...)。日常返回 dict 是「简写」，要精细控制就换 JSONResponse。
04

对照③请求里有什么（拆包清单）

同一条请求，两边都能拿到 URL、查询参数、请求头。下面把访问方式并列出来。

Laravel 13 · PHP
// $r = Illuminate\Http\Request $r->url(); # 完整 URL $r->path(); # 路径 $r->query('q'); # 查询参数 $r->header('x-token'); # 请求头 $r->input('name'); # body 字段
FastAPI 0.140 · Python
# req: Request req.url # 完整 URL req.url.path # 路径 req.query_params # 查询参数 req.headers # 请求头 # body 字段用参数声明： name: str = Body(...) # 或 Pydantic
Laravel 把「取查询/取头/取 body」都收进一个 $request 对象（方法/属性混用）；FastAPI 则是属性 + 参数声明双轨——简单字段用类型提示自动拆，复杂读取才动用 Request 对象。
05

⚠️ Laravel 老手常见坑

坑 1 · 忘了给函数加 Request 参数：FastAPI 不会像 Laravel 那样「全局总有 $request」。需要请求对象就显式写 req: Request 在签名里，否则函数拿不到。
坑 2 · 返回 dict 却想改状态码：直接 return {...} 永远 200。要 201/401 等自定义状态码或自定义头，必须包一层 JSONResponse(...)，不能依赖 return。
坑 3 · Header 名大小写/连字符：FastAPI 参数名 x_token 自动映射到 HTTP 头 x-token（连字符↔下划线）；写错名字会一直是 None。Laravel 的 $r->header('x-token') 则要带连字符原样写。

07

上手练习（10 分钟）

给 /ep04/echo 加一个查询参数读取，并让 /ep04/custom 多返回一个自定义头：

FastAPI · 你的练习
# 在 ep04.py 里改： @router.get('/echo') def echo(req: Request, q: Optional[str] = Query(None), x_token: Optional[str] = Header(None)): return {'path': req.url.path, 'q': q, 'token': x_token} # custom 再加一个头： headers={'x-powered-by': 'fastapi', 'x-hello': 'world'}
做完你会发现：加查询参数只是多写一个类型提示 q: Optional[str] = Query(None)，和 Laravel $r->query('q') 同构——只是 FastAPI 把「取值」前置成了函数签名。难点在「签名里声明」的习惯。
