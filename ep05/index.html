EP05 · 校验与序列化

一个 Pydantic包揽三件事

「进来要校验、出去要序列化」是写接口逃不掉的两件苦差。Laravel 要Form Request（校验）+ API Resource（序列化）两样东西分头写；FastAPI 只要一个 Pydantic model，校验、序列化、文档 schema 一次全包。本篇讲清这个「一对多」的落差。

01

一句话心智模型

两边都要回答同一个问题：「客户端传来的数据，先按规则拦一遍，再按样子还回去」。Laravel 把「拦」和「还」拆成两个类；FastAPI 把同一份数据形状既当进门门槛、又当出门镜子。

Laravel 的校验与序列化
  • Form Request 写 rules() 做校验
  • API Resource 写 toArray() 做序列化
  • 两个类 + 一份路由，三处维护同一份字段
FastAPI 的校验与序列化
  • 一个 Pydantic model 同时当校验规则
  • 同一个 model 也负责响应序列化
  • /docs 的 schema 自动从类型推导
一句话：Laravel 是「分而治之」（两个类各管一头），FastAPI 是「一图两用」（一份类型既当门禁又当镜子）。字段改一次，两边同步的成本完全不同。
02

对照①请求校验

同一个 POST /users，左 Laravel 在控制器里 $request->validate()，右 FastAPI 把 model 标成函数参数就完事——校验规则写在类型里，框架自动拦。

Laravel 13 · PHP
// routes/api.php Route::post('/users', [UserController::class, 'store']); // app/Http/Controllers/Api/UserController.php public function store(Request $request) { $data = $request->validate([ 'name' => 'required|string', 'email' => 'required|email', 'age' => 'nullable|integer', ]); return response()->json([ 'received' => $data]); }
FastAPI 0.140 · Python
# fastapi/app/ep05.py @router.post("/users", response_model=UserOut, status_code=201) def create_user(payload: UserCreate): # 缺字段 / email 非法 → 422 return UserOut(id=1, name=payload.name, email=payload.email)
Laravel 的 rules() 是字符串管道（required|email），靠框架解析；FastAPI 直接吃 Python 类型 + 校验器（EmailStr），IDE 能补全、能静态检查。校验失败时 Laravel 抛 ValidationException（默认 422），FastAPI 内置直接回 422。
03

对照②一个 model 包三件事

Laravel 把「校验 / 序列化 / 文档」拆成 Form Request + Resource 两样；FastAPI 一个 UserCreate 全包了。下面左是 Laravel 的「两件套」示意，右是 FastAPI 的真实 model（取自 ep05.py）。

Laravel 13 · PHP（两件套）
// 1) Form Request 管「进」 class CreateUserRequest extends FormRequest { public function rules() { return [ 'name' => 'required|string', 'email' => 'required|email', 'age' => 'nullable|integer', ]; } } // 2) API Resource 管「出」 class UserResource extends JsonResource { public function toArray($r) { return ['name' => $this->name, 'email' => $this->email]; } }
FastAPI 0.140 · Python（一个 model）
# 进：UserCreate 校验；出：UserOut 序列化 class UserCreate(BaseModel): name: str email: EmailStr age: Optional[int] = None class UserOut(BaseModel): id: int name: str email: EmailStr # 不暴露 age
Laravel 的 toArray() 是手写映射，想改响应字段就改这里；FastAPI 用 model_dump() 直接倒出。想「只回部分字段」时，Laravel 再写个 Resource，FastAPI 再定义个 UserOut model——思路一致，只是 FastAPI 少了「请求用什么、响应用什么」两套命名。
04

对照③可选与嵌套字段

「age 可空」「email 必须像邮箱」这类约束，两边写法不同但同构。右 FastAPI 的 Optional[int] = None 与 EmailStr 是真实代码；左对应 Laravel 的 nullable|integer 与 email 规则。

Laravel 13 · PHP
// rules() 里的约束写法 'email' => 'required|email', 'age' => 'nullable|integer', // 嵌套：数组字段用 * 通配 'tags.*' => 'nullable|string',
FastAPI 0.140 · Python
# 可选字段：默认值 None age: Optional[int] = None # 邮箱校验器（需装 email-validator） email: EmailStr # 嵌套：再定义一个 BaseModel class Tag(BaseModel): label: str tags: list[Tag] = []
嵌套对象两边都是「再定义一层结构」：Laravel 用 tags.* 规则 + 手动读数组；FastAPI 直接嵌套另一个 BaseModel，类型即文档，/docs 里能看到完整的子 schema。
05

⚠️ Laravel 老手常见坑

坑 1 · EmailStr 不报错但静默失效：EmailStr 依赖 email-validator 包，没装时校验不会按邮箱拦。装 FastAPI 时要 pip install "pydantic[email]" 或单独装 email-validator，否则 EmailStr 退化成不校验。
坑 2 · 嵌套 model 忘了加默认 / 类型：嵌套字段必须标成 list[SubModel] 这类明确类型，写 list 不带元素类型，FastAPI 不知道子结构，/docs 里也塌成空。Laravel 这边则是忘了 tags.* 规则，嵌套数组不会被逐条校验。
坑 3 · 422 自动返回，别自己 try：FastAPI 校验失败自动回 422 JSON（含每个字段的错误），不需要你手动 try/except。Laravel 里 $request->validate() 失败也会自动 422，但很多人习惯自己包一层——对齐心智：两套框架都帮你兜住了。
06

三步，跑起来

terminal
~ ❯ uvicorn app.main:app --reload → 打开 http://127.0.0.1:8000/docs 试 POST /ep05/users（故意传错 email 看 422） ~ ❯ curl -X POST http://127.0.0.1:8000/ep05/users \ -H 'Content-Type: application/json' \ -d '{"name":"会勇","email":"not-an-email"}' → 422：{"detail":[{"loc":["body","email"],...}]}
把仓库里 fastapi/app/ep05.py 跑起来：UserCreate 标成参数后，任何不合规的 body 都会被自动拦成 422。/docs 里还能直接看到 UserCreate 的 schema 表单——这是 Pydantic「一图两用」最直观的好处。
07

上手练习（10 分钟）

给 UserCreate 加一个「注册时可选填」的字段 is_active: bool = True，再新增一个只负责「出门」的 UserOut model（不含多余字段），把 create_user 改成返回 UserOut。改完用上面的 curl 验证：传不传 is_active 都应成功。

FastAPI · 你的练习
# 在 fastapi/app/ep05.py 里加： class UserOut(BaseModel): name: str email: EmailStr is_active: bool = True @router.post("/users") def create_user(payload: UserCreate) -> UserOut: return UserOut(**payload.model_dump())
做完你会发现：UserCreate（进门）和 UserOut（出门）是 FastAPI 里最常见的「双 model」分工——等价于 Laravel 的 Form Request + Resource。难点不在语法，在「什么时候该分两个 model」的判断习惯。
