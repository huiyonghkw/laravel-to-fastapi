EP14 · 部署

上线的两种姿势

Laravel 走 Nginx + PHP-FPM（进程池接 PHP）；FastAPI 走 Uvicorn / Gunicorn + ASGI（事件循环接 Python）。目标一样——把请求交给应用；差别在「谁来接管连接、进程怎么铺」。

01

一句话心智模型

两边都不让应用直接裸奔在互联网上：前面放一个反向代理，后面放一个应用服务器（进程模型）。Laravel 的应用服务器是 PHP-FPM，FastAPI 的是 Uvicorn（常配 Gunicorn 管多进程）。

Laravel 的部署
  • Nginx 反代 + 静态文件
  • PHP-FPM 进程池执行 PHP（同步）
  • .env 配环境，php artisan 管运维
FastAPI 的部署
  • Nginx / 云 LB 反代 + 静态文件
  • Uvicorn 跑 ASGI（单进程事件循环）
  • Gunicorn 管多进程，拉 Uvicorn worker
一句话：Laravel 是「Web 服务器 → FPM 进程池」，FastAPI 是「Web 服务器 → Uvicorn/Gunicorn 进程」。前者同步多进程，后者异步事件循环 + 多进程。
02

对照①反代配置

Laravel 用 Nginx 把 .php 交给 PHP-FPM（FastCGI）；FastAPI 用 Nginx 把请求转给 Uvicorn（HTTP）。左是真实 Nginx 示意，右是 FastAPI 侧同位置的 Nginx 段。

Laravel 13 · Nginx
# /etc/nginx/sites-enabled/app server { root /var/www/html/public; location / { try_files $uri /index.php$is_args$args; } location ~ \.php$ { fastcgi_pass unix:/run/php/php-fpm.sock; include fastcgi_params; fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name; } }
FastAPI 0.140 · Nginx
# /etc/nginx/sites-enabled/app server { location / { proxy_pass http://127.0.0.1:8000; proxy_set_header Host $host; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; } }
关键差异：Laravel 走 FastCGI 协议（fastcgi_pass 连 FPM socket）；FastAPI 走普通 HTTP 反代（proxy_pass 连 Uvicorn 端口）。两边静态文件都交给 Nginx 直接返回，不进应用。
03

对照②应用服务器 / 启动

Laravel 由 PHP-FPM 常驻、Nginx 触发；FastAPI 由 Gunicorn 拉起多个 Uvicorn worker。右取自仓库真实 fastapi/Dockerfile 与 ep14.py 注释。

Laravel 13 · PHP-FPM
# PHP-FPM 常驻（systemd 管） systemctl enable --now php-fpm # 应用代码更新后无需重启 FPM # 队列等后台任务单独起 worker： php artisan queue:work # 运维命令 php artisan config:cache php artisan route:cache
FastAPI 0.140 · Gunicorn
# 生产多进程（Dockerfile CMD） gunicorn app.main:app \ -k uvicorn.workers.UvicornWorker \ -w ${WORKERS} -b ${HOST}:${PORT} # 开发单进程热重载 uvicorn app.main:app --reload # ep14.py 暴露 /ep14/env 看运行环境
PHP-FPM 自带进程池（pm.max_children 配并发）；FastAPI 这里用 Gunicorn 当进程管理器、-w 指定 worker 数，每个 worker 是一个 Uvicorn 事件循环。-k UvicornWorker 是桥接 ASGI 的关键。
04

对照③容器化打包

Laravel 通常打包进带 Nginx+PHP-FPM 的基础镜像；FastAPI 用官方 Python 镜像 + Gunicorn。右是仓库真实 fastapi/Dockerfile 全文。

Laravel 13 · 思路
# 典型多阶段：composer 装依赖 # 最终镜像同时跑 Nginx + FPM # （supervisor 或双进程） # COPY . /var/www/html # CMD ["nginx", "-g", "daemon off;"] # + php-fpm 同容器常驻
FastAPI 0.140 · Dockerfile
FROM python:3.12-slim WORKDIR /app COPY requirements.txt . RUN pip install --no-cache-dir \ -r requirements.txt COPY app ./app ENV HOST=0.0.0.0 PORT=8000 WORKERS=4 EXPOSE 8000 # 生产：Gunicorn + Uvicorn worker CMD gunicorn app.main:app \ -k uvicorn.workers.UvicornWorker \ -w ${WORKERS} -b ${HOST}:${PORT}
FastAPI 镜像只跑应用进程（Uvicorn/Gunicorn），Nginx 一般在镜像外（宿主或前置 LB）。Laravel 常见「Nginx+FPM 同镜像」是历史习惯；在容器时代，前后分离部署更干净。
05

⚠️ Laravel 老手常见坑

坑 1 · 生产别裸跑 Uvicorn：uvicorn --reload 是开发用的单进程。生产要 Gunicorn + UvicornWorker 拉多进程（如 -w 4），否则并发上不去、进程挂了没人拉。
坑 2 · 静态文件别走 Uvicorn：像 Laravel 把静态资源交给 Nginx 一样，FastAPI 的 /static 也要由 Nginx（或 CDN）直接返回，不要让 Python 进程去读磁盘——这是 Laravel 老手最容易惯性失误的点。
坑 3 · 健康检查与日志：PHP-FPM 挂了 Nginx 直接 502；Uvicorn 同理。务必暴露一个轻量 GET /ep14/env 之类端点给 LB 探活，并把访问日志接到 Nginx / 容器 stdout，别只依赖框架内部日志。
06

三步，跑起来

terminal
~/hekouwang-laravel-to-fastapi ❯ docker build -t lf-api -f fastapi/Dockerfile . → 构建镜像（含 gunicorn 启动） ~/hekouwang-laravel-to-fastapi ❯ docker run -p 8000:8000 -e WORKERS=4 lf-api → 容器起 4 个 Uvicorn worker ~/hekouwang-laravel-to-fastapi ❯ curl localhost:8000/ep14/env → {"worker":"4","host":"0.0.0.0","port":"8000"}
把仓库 fastapi/ 跑起来：/ep14/env 直接返回当前 worker 数、host、port，确认「跑在哪」。Nginx 前置时把 proxy_pass 指向 8000 即可，静态资源交给 Nginx。
07

上手练习（10 分钟）

给容器加一个 Nginx 前置层，让静态资源不进 Python：

FastAPI · 你的练习
# nginx.conf 里加静态段（在 / 之前） location /static/ { alias /app/static/; # 直接返回 expires 1d; } # 再用 docker-compose 把 nginx:8000 → app:8000 # 验证：curl 静态文件不再经 Uvicorn
做完你会发现：FastAPI 的「Nginx 前置 + 静态直出」和 Laravel 的 try_files 心智完全一致——只是 Laravel 多一层 FastCGI 协议，FastAPI 是纯 HTTP 反代。
