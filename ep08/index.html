EP08 · 事务与关联

要么全成，要么全回滚

「下订单」要同时写订单和订单项，两步必须绑成一步——这就是事务。顺带把「关联数据怎么一起查」讲清。Laravel 用 DB::transaction，FastAPI 用 with db.begin()；关联两边都靠「预加载」避免 N+1。

01

一句话心智模型

事务就是「一组写操作，要么全成功提交，要么任一步失败就整体回滚」。关联查询则是「主表 + 从表，一次取回，不要一条条查」。两个心智，两边一一对应。

Laravel 的事务 / 关联
  • DB::transaction(fn () => ...) 闭包包住写操作
  • 闭包里抛异常 → 自动 rollback
  • 关联查询用 Model::with('items') 预加载
FastAPI 的事务 / 关联
  • with db.begin(): 上下文管理器包住写操作
  • 块内抛异常 → 退出时自动 rollback
  • 关联用 SQLAlchemy relationship + joinedload 预加载
一句话：Laravel 用闭包包裹事务，FastAPI 用 with 块包裹事务。同一个心智，两种落笔。
02

对照①事务：写订单

「开事务 → 写订单 → 提交；中途报错就回滚」。左 Laravel 把代码塞进 DB::transaction 闭包，右 FastAPI 把代码塞进 with db.begin(): 块。

Laravel 13 · PHP
// routes/api.php — /orders return \Illuminate\Support\Facades\DB::transaction( function () { $order = \App\Models\Order::create([ 'amount' => 100, ]); return ['id' => $order->id, 'amount' => $order->amount]; // 抛异常 → 自动 rollback });
FastAPI 0.140 · Python
# ep08.py — POST /orders @router.post("/orders") def create_order(db=Depends(get_db)): with db.begin(): # 事务开始 o = Order(amount=100) db.add(o) # 块内抛异常 → 退出自动 rollback return {"id": o.id, "amount": o.amount}
两边都是「成功自动提交，异常自动回滚」。FastAPI 的 with db.begin(): 进入就 BEGIN，离开就 COMMIT；若离开时带着未捕获异常，则 ROLLBACK。
03

对照②关联查询：订单 + 订单项

查订单时连同它的订单项一起取回，不要在循环里逐条查（N+1）。左 Laravel 用 with('items')，右 FastAPI 用 relationship + joinedload。

Laravel 13 · PHP
// Eloquent 预加载从表 $orders = \App\Models\Order::with('items') ->get(); foreach ($orders as $o) { // 已随主表一次取回，不再查库 $o->items; }
FastAPI 0.140 · Python
# SQLAlchemy 预加载从表 from sqlalchemy import select from sqlalchemy.orm import joinedload stmt = select(Order).options( joinedload(Order.items)) orders = db.execute(stmt).unique().scalars().all() for o in orders: o.items # 已在 JOIN 里取回
with('items') ≈ joinedload(Order.items)，都是一次性把关联数据 JOIN/批量取回。不做预加载时，每条订单访问 items 都会再发一条 SQL，就是经典的 N+1。
04

对照③事务里写关联（组合）

真实下单：同一事务里写订单 + 写订单项，任一步失败整体回滚。这是事务和关联的交汇点。

Laravel 13 · PHP
// 一个事务写两张表 return DB::transaction(function () { $order = Order::create([ 'amount' => 100]); $order->items()->create([ 'sku' => 'A-1', 'qty' => 2]); return $order->load('items'); });
FastAPI 0.140 · Python
# 一个事务写两张表 with db.begin(): o = Order(amount=100) db.add(o) db.flush() # 拿到 o.id db.add(OrderItem( order_id=o.id, sku='A-1', qty=2)) return o # 提交后返回
关键差异：SQLAlchemy 需要先 db.flush() 拿到主表自增 id，才能填从表的order_id；Eloquent 的 $order->items()->create() 内部已帮你做掉了这步。其余逻辑完全同构。
05

⚠️ Laravel 老手常见坑

坑 1 · 忘了 flush 就拿 id：FastAPI 里 db.add(o) 后 id 还没生成，直接读 o.id 会得到 None。先 db.flush()（仍在事务内）再取 id 写从表。
坑 2 · 异常被「吃掉」不回滚：with db.begin(): 只在未捕获异常时回滚。若你在块里 try/except 吞掉了异常，事务会照常提交。要回滚就把异常再抛出，或手动 db.rollback()。
坑 3 · 关联忘了预加载：o.items 在循环里逐条触发查询就是 N+1。写查询时顺手加 with('items') / joinedload(Order.items)，和 Laravel 习惯一致。

07

上手练习（10 分钟）

把「对照③」的组合事务补完整：在 ep08.py 的 create_order 里加一行 OrderItem，并加一个读接口返回订单及其订单项。

FastAPI · 你的练习
# 在事务块内补写订单项： db.add(OrderItem(order_id=o.id, sku='A-1', qty=2)) # 加一个读接口（带预加载） @router.get("/orders/{oid}") def get_order(oid: int, db=Depends(get_db)): stmt = select(Order).options( joinedload(Order.items) ).where(Order.id == oid) return db.execute(stmt).unique().scalars().first()
做完你会发现：事务保证「订单+订单项」要么都写入、要么都回滚；读接口加 joinedload 一次取回关联——和 Laravel with('items') 完全同构。难点不在 ORM，在「把写操作关进同一个事务块」。
