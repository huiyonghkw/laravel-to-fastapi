EP15 · 收官

选型决策树

前面 14 期把两边的功能一一对照完了。最后一期不写新框架，而是把这棵「什么时候用哪个」的判断树收拢成一条可调用规则——对照你手上的项目特征，直接给建议。

01

一句话心智模型

两个框架没有高下，只有合不合适。判断标准不是「哪个更先进」，而是「项目特征」对上「框架强项」。Laravel 强在全栈一把梭，FastAPI 强在纯 API / 异步 / AI。

Laravel 的适用场景
  • 要渲染页面 / 全栈 MVC / Blade
  • 团队 PHP 储备深，交付要快
  • 后台、CMS、电商、传统 Web 应用
FastAPI 的适用场景
  • 纯后端 API / 微服务 / 流式响应
  • 高并发 I/O、WebSocket、异步红利
  • AI / ML 服务、数据科学接口
一句话：Laravel 是「全栈瑞士军刀」，FastAPI 是「API 与 AI 的手术刀」。先看项目长什么样，再选工具。
02

对照①决策入口（路由）

两边都在 /advise 暴露一个 POST 端点，收一组项目特征、返回一个选型结论。左 Laravel 在 routes/api.php 闭包里收口，右 FastAPI 用路径操作函数。

Laravel 13 · PHP
// routes/api.php — EP15 决策入口 Route::post('/advise', function ( \Illuminate\Http\Request $r) { // 真实项目用 Policy/Service 计算 // 此处给入口骨架 return ['pick' => $r->input('has_frontend') ? 'Laravel' : 'FastAPI']; });
FastAPI 0.140 · Python
# ep15.py from fastapi import APIRouter from pydantic import BaseModel router = APIRouter() @router.post("/advise") def advise(p: ProjectProfile): ... # 见对照③
同一道门：POST /advise 收「项目特征」、吐「选型结论」。Laravel 把决策逻辑推到 Service/Policy 类（本页骨架只示意入口）；FastAPI 把决策逻辑直接写在路径操作函数里。
03

对照②项目特征（请求模型）

判断树吃三类特征：是否要前端、是否要实时、团队是否熟 PHP。右边用 Pydantic 模型显式声明；左边靠 Request 取参（真实项目会用 Form Request 校验）。

Laravel 13 · PHP
// 取参（骨架，未含校验） $hasFrontend = $r->boolean('has_frontend'); $needRealtime = $r->boolean('need_realtime'); $teamKnowsPhp = $r->boolean('team_knows_php'); // 生产建议用 Form Request： // rules() 里 boolean 校验
FastAPI 0.140 · Python
# ep15.py — 显式请求模型 class ProjectProfile(BaseModel): has_frontend: bool # 是否要渲染页面/全栈 need_realtime: bool # 是否要流式/高并发 I/O team_knows_php: bool # 团队 PHP 储备
FastAPI 的 ProjectProfile 把字段 + 类型 + 文档一次说清，请求进来自动校验、自动进 /docs。Laravel 侧的等价物是 Form Request 类——只是本页骨架为求简洁直接取参。
04

对照③决策函数核心

真正的判断树。右 FastAPI 是 ep15.py 里的真实 advise() 本体；左 Laravel 给出与之一一对应的同构实现（生产里会收进 Service 类，逻辑完全一致）。

Laravel 13 · PHP
// 与 ep15.py advise() 同构 if ($hasFrontend) { $pick = 'Laravel'; $why = '要渲染页面/全栈，Laravel 开箱即用'; } elseif ($needRealtime) { $pick = 'FastAPI'; $why = '高并发 I/O / 流式响应，异步红利明显'; } elseif ($teamKnowsPhp) { $pick = 'Laravel'; $why = '团队 PHP 熟，先用 Laravel 交付'; } else { $pick = 'FastAPI'; $why = '纯后端 API，FastAPI 更轻更显式'; } return ['pick' => $pick, 'why' => $why];
FastAPI 0.140 · Python
# ep15.py — advise() 本体 if p.has_frontend: pick = "Laravel" why = "要渲染页面/全栈，Laravel 开箱即用" elif p.need_realtime: pick = "FastAPI" why = "高并发 I/O / 流式响应，FastAPI 的异步红利明显" elif p.team_knows_php: pick = "Laravel" why = "团队 PHP 熟，先用 Laravel 交付" else: pick = "FastAPI" why = "纯后端 API，FastAPI 更轻更显式" return {"pick": pick, "why": why}
判断顺序就是权重：全栈 > 实时/异步 > 团队资产 > 默认轻量 API。两边 if/elif 链逐字对应，心智完全相同，差别只在语法（elseif vs elif）。
05

⚠️ Laravel 老手常见坑

坑 1 · 以为有「银弹框架」：没有哪个框架通吃。要渲染页面就 Laravel，要纯 API/AI 就 FastAPI。决策树先问「项目长什么样」，别先问「哪个更潮」。
坑 2 · 低估团队熟悉度权重：决策树里 team_knows_php 排在实时之后、默认之前。团队会用、能快速交付，往往比「技术更优」更重要——尤其 deadline 紧的时候。
坑 3 · AI / ML 项目硬上 Laravel：Python 生态（PyTorch、transformers、pandas）是 AI 项目的母语。要写推理服务、流式 token，FastAPI 几乎是无摩擦选择；用 PHP 反而处处绕路。

上手练习（10 分钟）

need_ai 已在仓库代码里落地。请再加一条：「团队 < 3 人且纯 API → 优先 FastAPI（小团队少约定）」，给 ProjectProfile 加 team_size: int = 5，并写一条 pytest。

FastAPI · 你的练习
# ProjectProfile 加字段 team_size: int = 5 # advise() 在合适位置插入： elif (not p.has_frontend) and p.team_size < 3: pick = "FastAPI" why = "小团队纯 API，少约定优先" # 加一条 pytest 断言 pick == FastAPI
做完你会发现：判断树是可逐步生长的。交互区与 API 规则保持一致——改代码后记得同步改本页脚本。
